--- Item 1: N >= 10^4 spectral-dimension asymptotics ---
Reviewer asked for matrix-free shift-invert Arnoldi on a 2N x 2N block
matrix M=[[A,I-D],[I,0]]. That block form does not correspond to this
project's actual eigenproblem (L_sym is a plain N x N symmetric operator)
and, more importantly, heat_trace needs the FULL spectrum, which
shift-invert (eigenvalues near one shift) doesn't give economically.
Implemented instead: matrix-free Stochastic Lanczos Quadrature (SLQ) --
sparse.rs (CSR-equivalent adjacency list, O(N+E) matvec) +
spectral_trace.rs (Hutchinson trace estimator + Lanczos Gauss quadrature,
Ubaru/Chen/Saad 2017). Two real bugs caught by unit tests before trusting
any output: (1) tridiagonal off-by-one (m alphas need m-1, not m, betas),
(2) unnormalized Lanczos start vector. Fixed; SLQ now matches exact dense
heat_trace on small test graphs to <3% (200 probes) / <2% (full-rank
Krylov, isolating quadrature exactness from Hutchinson MC variance).

Verified at N=2000 (d=4) against dense diagonalization directly:
  dense SymmetricEigen: 9.60s   SLQ (40 probes, 60 steps): 0.26s
  max |d_s_exact - d_s_SLQ| over a 23-point t-sweep: 0.042
    (worst case at the largest t, where P(t) is small and the log-
    derivative is intrinsically noisy -- matches heat_kernel.rs's own
    documented IR-artifact caveat, not a new problem)

Then ran matrix-free only at N=10,000 (d=4): graph build 1.6ms,
80-probe/80-step/40-point SLQ sweep in 4.6s. d_s(t) rises smoothly from
~0 (UV cutoff) to a peak of ~7.67 around t~26, then falls -- NOT a flat
plateau. This is the mathematically expected result for a random regular
graph, not a shortfall of the method: random regular graphs are locally
tree-like (that's why Kesten-McKay applies at all), and trees don't have
a fixed local dimension for d_s to plateau at. A genuine plateau would
need a graph model with bounded local geometry (the hyperbolic
tessellation / Bolza-surface direction already on this project's roadmap
elsewhere), not this configuration-model expander.

--- Item 2: Bulk spacing statistics of B (Ginibre vs Poisson) ---
Empirically corrected the "unreliable Schur" note above (continuum_
limit.rs, ramanujan_diagnostic doc comment): nalgebra's non-symmetric
Schur solver is NOT unreliable per se, it just needs a far larger
max_niter than the default. Verified: N=1000 dense random matrix fails
to converge at max_niter=1000, converges correctly (trace matches
sum(Re(eigenvalues)) to 6e-12) at max_niter=20000, taking 3.7s. Measured
scaling on actual B matrices (d=4): N=100/m2=400 -> 76ms, N=200/m2=800
-> 683ms, N=400/m2=1600 -> 5.8s, N=800/m2=3200 -> 71.6s (roughly O(m^3),
consistent with a dense QR-algorithm solver) -- all converged, all with
trace-identity error ~1e-12. This bounds what's honestly reachable for a
1000-seed ensemble: chose N=120 (m2=480, ~140ms/seed) specifically
because that makes 1000 real seeds tractable in minutes, not because
1000 was convenient to claim without running it.

Built bulk_spacing.rs: complex_eigenvalues (corrected Schur), empirical
(not formula-based) Ginibre and Poisson reference ensembles, k-NN local-
density unfolding, nearest-neighbor spacing, KS-distance comparison.
Unit-tested that the method itself correctly separates repulsion
(Ginibre) from no-repulsion (Poisson) on the *references* before trusting
it on B.

First full run crashed (NaN in KS distance -- a real bug, not swept
under the rug): traced to exact eigenvalue coincidences in B causing
zero nearest-neighbor distances. Root cause identified and *verified*,
not just patched: Bass's theorem (already relied on elsewhere in this
crate, see ihara_and_bass_formulas_agree) says B has eigenvalue +1 with
multiplicity exactly m-n and -1 with multiplicity exactly m-n. For
N=120, d=4: m-n=120. Verified directly: 121 eigenvalues within 1e-6 of
+1, 120 within 1e-6 of -1 (matches theory to the expected 1-off, a
genuine non-trivial eigenvalue landing near +1). Fixed by excluding this
exactly-degenerate trivial block before any bulk statistic (see
drop_bass_trivial_eigenvalues), plus defensive finite-value filtering as
a second safety net. Added a regression test for exactly this scenario.

Re-ran the full pipeline (1000 B seeds + 200 Ginibre-reference seeds +
200 Poisson-reference seeds, all matrix size m2=480, wall time ~220s
total): B's "bulk" spacing distribution came out with MORE small
spacings than even the Poisson reference (52% below the 0.3 threshold,
vs 22% for Poisson and 6% for Ginibre) -- the opposite of what
"chaotic/repulsive" would predict, and a red flag rather than an answer.

Investigated rather than reported at face value. Bass's formula gives
each non-trivial B eigenvalue as a root of u^2 - lambda_A*u + (d-1) = 0
for each adjacency eigenvalue lambda_A. When |lambda_A| <= 2*sqrt(d-1)
(true for effectively all of A's spectrum by Kesten-McKay), the roots
are complex with |u| = sqrt(d-1) EXACTLY. Verified directly on the
N=120, d=4 test graph: 99.58% of non-trivial B eigenvalues sit within 1%
of radius sqrt(3)=1.732051; median/p10/p90 radius all equal 1.732051 to
6 decimal places. So for a *regular* graph, B's "bulk" is not a 2D point
cloud at all -- it is (to >99% precision) confined to a single circle.
The Ginibre-vs-Poisson 2D framing the reviewer asked for is testing the
wrong null model for this object: a 2D local-density unfolding
systematically manufactures small spacings out of points that are
actually constrained to a 1D curve, which is exactly the "more small
spacings than Poisson" artifact observed above. The well-posed question
for a regular graph's non-backtracking spectrum is a 1D CIRCULAR
ensemble comparison (angular spacings around the circle |u|=sqrt(d-1):
CUE-type repulsion vs uniform/Poisson on the circle), not this one.
Not implemented this session -- flagging precisely and stopping here
rather than quietly forcing the existing 2D machinery to produce a
number for the wrong question.

Session addition: Regge calculus (Regge action, path integral, and the
honestly-scoped discrete residue of "diffeomorphism invariance")
=======================================================================

Added src/regge.rs, src/regge_pi.rs, tests/regge_tests.rs, src/bin/regge_demo.rs.
`cargo test --release`: 23/23 tests pass (7 original + 8 new Regge tests +
0 doctests after fencing two accidentally-doctested equations in module docs).

What's implemented:
  - A 3D simplicial complex (tetrahedra as literal 3-simplices, built from
    4-vertex hyperedges rather than clique-expanding them away).
  - Regge's edge-length formulation: no ambient embedding of the whole
    complex is assumed. Edge lengths are the metric degrees of freedom;
    validity of each tetrahedron is checked via the Cayley-Menger
    determinant (generalized triangle inequality).
  - Dihedral angles per tetrahedron via a local embedding (always exists,
    unique up to rigid motion, for a valid tetrahedron) -- verified against
    the closed-form regular-tetrahedron volume l^3/(6*sqrt(2)) to 2.22e-16.
  - Deficit angles at hinges (edges) and the Regge action
    S = sum_hinges L_hinge * delta_hinge, the exact discretization of
    integral(R sqrt(g)).
  - A Metropolis path integral Z = integral D[length] exp(-kappa*S) over
    edge lengths at fixed connectivity (quantum Regge calculus, Rocek &
    Williams 1981 / Hamber).

Two test failures on first run, both real physics/geometry, not bugs --
investigated and correctly reclassified rather than patched to pass:

(1) A 5-tetrahedra decomposition of a flat cube (central regular tet on
    alternate corners + 4 corner tets) gave deficit angle EXACTLY pi, not
    0, at every shared hinge. Diagnosis: every edge of the central
    tetrahedron is a face DIAGONAL of the cube -- i.e. lies on the
    boundary, not the interior. A flat BOUNDARY hinge's dihedral angles
    sum to pi (half the solid angle budget), not 2*pi, so the interior
    convention (2*pi - sum) correctly reads exactly pi on a flat boundary
    hinge. Renamed the test to assert exactly that
    (flat_cube_five_tets_boundary_hinges_read_pi_not_zero) rather than
    force a false "zero action" claim -- this module explicitly does not
    implement a separate boundary term (the discrete analogue of the
    Gibbons-Hawking-York term), and this test now documents why that
    matters instead of silently getting it wrong.

    Replaced the intended triangulation-independence check with a version
    that actually has a genuine INTERIOR hinge on both sides: two
    completely different 6-tetrahedra decompositions of the same flat unit
    cube, fanning around its two different main diagonals (0-7 and 1-6),
    checked independently. Result: both report deficit angle 2.665e-15 rad
    (float noise) and total action 4.615e-15 -- agreeing with each other
    to 0.0 within reported precision. This is the honestly-scoped claim:
    physics of a flat region is independent of which triangulation
    describes it (an exact discrete fact), not full continuum
    diffeomorphism invariance for curved configurations (which Regge
    calculus is well documented to only approximately recover in the
    continuum limit, e.g. via the discrete Bianchi identity literature).

(2) The path-integral coupling test asserted <|S|> should shrink as kappa
    (~1/G) grows, on the naive expectation that stronger gravitational
    coupling enforces flatness more strongly. It does the opposite:
    kappa=0.2 -> <S>=-4.88, kappa=1.0 -> <S>=-11.70, kappa=5.0 ->
    <S>=-20.69 (acceptance rate dropping 95%->77%->12% as it runs up
    against the hard tetrahedron-validity wall). Verified this is not a
    sign bug by checking the underlying mechanism directly: the Regge
    curvature term sum(L*deficit) is NOT bounded below -- a hinge can
    carry an arbitrarily large negative deficit angle (a locally
    "excess-angle" gluing), and Metropolis weight exp(-kappa*S) GROWS as S
    becomes more negative, so stronger kappa pulls harder toward such
    configurations, not away from them, bounded only by geometric
    validity. This is the discrete incarnation of the conformal-factor
    problem in Euclidean quantum gravity (Gibbons, Hawking & Perry 1978),
    a well-known, genuine pathology of the naive real-weight Euclidean
    path integral -- not something this module attempts to cure (that
    needs a modified measure or a rotation of the conformal mode, both out
    of scope here). Rewrote the test to assert the actual, correct,
    monotonic-runaway-but-bounded behavior instead of the wrong naive
    expectation.

What this addition does NOT establish (same discipline as continuum_limit.rs):
  - No claim that any specific hypergraph/simplicial complex in this crate
    approximates a specific smooth spacetime.
  - No claim of continuum diffeomorphism invariance -- only the narrower,
    exact, triangulation-independence-of-flat-space fact described above.
  - No fix for the conformal-factor / unbounded-action pathology -- it is
    reported and correctly reproduced, not solved. A real quantum Regge
    calculus implementation would need a properly defined measure (e.g.
    a DeWitt measure on edge lengths) and/or a rotation of the conformal
    mode to make the Euclidean path integral well-defined; neither is
    implemented, and claiming otherwise would misrepresent a known open
    problem in the field as solved.

=== Addition: src/regge_eom.rs + src/cheeger.rs ===
Date: Mon Aug 24 2026

New evidentiary machinery, same "verify, don't assert" discipline as the
rest of this crate:

1. regge_eom.rs -- numerically verifies the Schlafli differential identity
   (Regge 1961): dS/dL_e = delta_e at every interior hinge, computed two
   independent ways (central finite difference of the FULL action vs. the
   bare deficit angle) and cross-checked. This is the actual reason the
   Regge action is a sensible discretization of GR at all -- vacuum field
   equations reduce to delta_e = 0 at every hinge, the discrete analogue of
   R_munu = 0.

   Real scope bug found and fixed while writing this (not silently
   patched): the identity was first tested on the flat cube used throughout
   regge_tests.rs and failed badly (numerical dS/dL off by ~10, not ~1e-9).
   Diagnosis: regge_action sums the curvature term over *interior* hinges
   only (mult >= 3) by design (no boundary/GHY term implemented, per
   regge.rs's own documented scope) -- but the cube has a boundary, so most
   of the edges of any tetrahedron touching the one interior hinge (the
   main diagonal) are boundary edges EXCLUDED from the action sum. The
   Schlafli cancellation needs every edge of every touching tetrahedron to
   itself be counted in S; on a complex with boundary it structurally isn't,
   so dS/dL_e != delta_e there -- correctly, not as a bug in this module.
   Fixed by testing on a genuinely closed complex instead: the boundary of
   a 4-simplex (5 tetrahedra, 10 edges, the minimal closed triangulated
   3-manifold, topologically S^3), where every edge has multiplicity
   exactly 3 by combinatorial construction and there is no boundary at all.
   There the identity holds to finite-difference precision (~1e-4 at h=1e-4,
   Richardson-checked across two step sizes) on both an irregular
   (5-points-in-R^4, no symmetry) and a regular (vertex-transitive) curved
   configuration. Tests: 3 passed.

2. cheeger.rs -- exact (brute-force, small-N) Cheeger constant / edge
   conductance h(G), cross-checked against the normalized-Laplacian
   spectral gap lambda_1 via Cheeger's inequality lambda_1/2 <= h(G) <=
   sqrt(2*lambda_1) (Chung, Spectral Graph Theory, Thm 2.2). Verified
   against closed-form values on C_10 and K_6, and the inequality itself
   verified on an irregular (non-vertex-transitive) bridge graph and a
   disconnected graph (both sides degenerate to 0 correctly). This
   complements continuum_limit.rs's Ramanujan/Alon-Boppana diagnostic with
   the purely combinatorial side of the same "how expander-like is this
   graph" question. Tests: 4 passed.

Both modules hit an unrelated rustdoc gotcha worth noting: module doc

Full suite after this addition: `cargo test --release --lib` = 24 passed

Goal: continuum_limit.rs (Step 3) correctly refuses to claim H_N -> a
specific smooth manifold -- that's a genuine open problem. This session
adds the narrowest honest, quantitative version of that question: does a
hypergraph discretization of a manifold with a KNOWN closed-form spectrum
(S^2, lambda_l = l(l+1)/R^2) converge as resolution N grows, at what rate,
and does the choice of discretization scheme (clique expansion vs. the
Zhou-Huang-Scholkopf normalized hypergraph Laplacian) matter. Used the
scale-free ratio lambda(l=2)/lambda(l=1) = 3 exactly, not raw eigenvalues,
specifically to sidestep the discretization-dependent bandwidth/scaling
constants that a raw-eigenvalue comparison would need to get right first.

Two real findings during development, investigated rather than glossed:

1. First test written (asserting the Zhou hypergraph Laplacian equals the
   clique-expansion normalized Laplacian exactly, on a plain graph encoded
   as size-2 hyperedges) FAILED: 1.0 vs 0.5000000000000001. The test's
   assumption was wrong, not the implementation. Hand-derivation (see the
   module doc comment) shows the correct relation is exactly a factor of
   (m-1)/m = 1/2 for m=2 -- not equality -- an intrinsic feature of Zhou's
   D_e^{-1} normalization convention, not a bug. Fixed the test to assert
   the correct 0.5 relation.

2. That derivation generalizes: for ANY hyperedge set where every hyperedge
   has the same size m (which is exactly what the original kNN hyperedge
   construction produces -- every vertex gets exactly k+1 members), the
   Zhou Laplacian equals (m-1)/m times the clique-expansion Laplacian
   EXACTLY, a pure global rescaling. Verified directly by comparing raw
   eigenvalues (not just the ratio) at N=200, k=10: eigs_B[i] = (10/11) *
   eigs_A[i] to float precision, across the full spectrum, not just the
   bands used for the ratio test. Consequence: the planned scheme-A-vs-
   scheme-B comparison was VACUOUS as originally designed -- a ratio-based
   test cannot see any difference between the schemes if hyperedge size is
   uniform, since a global rescaling cancels in a ratio. First full demo
   run (kNN hyperedges, k=10) confirmed this: ratio_A and ratio_B were
   numerically identical to 6 decimal places at every N tested. Not
   reported as a positive "schemes agree" result -- that would misrepresent
   a degenerate test setup as a substantive finding.

   Fixed by switching the comparison to `eps_ball_hypergraph`: one
   hyperedge per vertex containing every point within a fixed chordal
   radius (not a fixed count), so hyperedge size fluctuates with local
   sampling density and the (m-1)/m-per-hyperedge cancellation no longer
   applies uniformly. Verified hyperedge sizes actually vary
   (`eps_ball_hyperedges_have_varying_sizes`) and that the two schemes'
   ratios then genuinely diverge (`eps_ball_schemes_a_and_b_genuinely_
   diverge`, checked at N=800: schemes differ by >1e-4, not float noise).
   This construction is also the more standard one in the point-cloud-to-
   manifold convergence literature (Belkin-Niyogi-style epsilon-graphs),
   so the fix is better-motivated, not just a workaround.

3. The heuristic connectivity radius (`heuristic_eps`, c * sqrt(ln N / N))
   needed its constant tuned against measured data, not assumed correct.
   Swept c in {1.5, 2.0, 2.5, 3.0, 3.5, 4.0} at N in {100, 800, 3200} and
   counted near-zero Laplacian eigenvalues (the number of connected
   components) directly: c=1.5 left the graph badly disconnected (9-60
   components depending on N, growing WORSE at larger N, i.e. this
   specific constant doesn't just need a one-time fix but was actively
   wrong in its N-scaling); c=2.0 mostly-but-not-always connected (2
   components at some N); c=2.5 gave exactly 1 component (connected)
   uniformly across every N from 100 to 3200. This is the constant used in
   both the demo and the test suite; verified directly, not assumed to
   scale correctly just because the log(N)/N functional form is the
   textbook connectivity-threshold shape.

Session: addressed the four items flagged as "explicitly unsafe outside
narrow conditions" from the previous session's notes -- geodesics.rs's
fixed-step-only integration, tensor_calculus.rs's finite-difference-only
precision, regge_pi.rs's unbounded-below conformal mode, and
hypergraph_continuum_limit.rs's unexplained c=2.5 constant. One fix per
subsystem, each verified against a real test, not just written and
assumed correct.

1. tensor_calculus.rs precision (finite-difference -> exact autodiff).
   New module `autodiff.rs`: a `Scalar` trait plus `Jet2`, a forward-mode
   second-order jet (value + 4 first partials + 4x4 second partials),
   propagated through +,-,*,/,sqrt,sin,cos,powi,powf via the ordinary
   multivariate chain rule. `metrics.rs` got `*_generic<T: Scalar>`
   formulas so both the existing f64 path and the new Jet2 path share one
   source of truth (no risk of the two drifting apart). New
   `curvature_at_exact` in tensor_calculus.rs derives Christoffel/Riemann
   analytically from a Jet2-evaluated metric -- no finite-difference step,
   no truncation error. Key mathematical fact making Jet2 (2nd order, not
   higher) sufficient: the Riemann tensor needs only the metric's value and
   first two derivatives (Christoffel needs g^-1 and dg; differentiating
   once more needs d(g^-1) = -g^-1 dg g^-1, which only needs dg again, and
   d(dg) = d^2g, which Jet2.hess supplies directly -- no third derivative
   of g ever appears). Verified: Schwarzschild Kretschmann and Ricci-flatness,
   FRW Ricci scalar (with a(t)=t^(2/3) differentiated via Jet2.powf, not
   hand-derived -- an independent check against the hand-derived closed
   form), and Minkowski flatness, all to rel err < 1e-9 (vs. the
   finite-difference engine's 1e-2 to 1e-6 depending on quantity). 6 new
   tests in autodiff.rs + tensor_calculus.rs/metrics.rs.

2. geodesics.rs adaptive stepping. Added `AdaptiveConfig`, `AdaptiveError`,
   `adaptive_step`, `integrate_adaptive`: step-doubling Richardson error
   estimation (run one full RK4 step and two half-steps from the same
   starting state; the O(h^5) local truncation error is estimated directly
   from their difference / 15) drives automatic step-size control, with a
   PI-free growth/shrink controller. This is metric-agnostic in the same
   sense the rest of the module already is -- it doesn't need to "know"
   it's near a photon sphere, only that local error is growing there, which
   step-doubling detects directly. On failing to meet tolerance even at
   h_min, returns `AdaptiveError::StepSizeCollapsed` rather than silently
   returning an inaccurate trajectory.
   Honest note on getting the test right: my first attempt at a
   near-photon-sphere test used an impact parameter formula that was
   actually BELOW the exact photon-capture threshold (b_crit = 3*sqrt(3)/2
   * r_s ~= 2.598 r_s -- I'd written something dimensionally different that
   evaluated to ~2.36 r_s), so the "near photon sphere" trajectory was
   actually plunging toward the horizon, where Schwarzschild coordinates
   are genuinely singular (not just hard to integrate) -- correctly
   triggering StepSizeCollapsed, but not testing what I intended. Fixed by
   computing b_crit exactly and using a scattering trajectory 10% above it.
   3 new tests: adaptive shrinks well below a deliberately coarse nominal
   step size near the (correctly identified) photon sphere while
   conserving the norm invariant; adaptive matches the existing fixed-step
   result in the easy weak-field regime; an artificially impossible
   tolerance correctly triggers StepSizeCollapsed rather than hanging.

3. regge_pi.rs conformal-mode runaway. Full GHP-style contour rotation is
   a genuine open problem for a non-Gaussian action like full Regge
   calculus and stays out of scope (unchanged claim). What's now
   implemented: a volume-constrained (canonical ensemble) sampling mode
   (`VolumeConstraint`, `McConfig.volume_constraint`), the standard
   practical mitigation from the dynamical-triangulations/Regge Monte
   Carlo literature for exactly this problem. Mechanism: pure global
   rescaling of every edge length leaves every dihedral angle exactly
   invariant (angles depend only on length ratios within a tetrahedron),
   so it's precisely the runaway direction the existing pathology test
   documents (curvature term scales linearly and unboundedly in the scale
   factor, and Cayley-Menger validity -- the sampler's only hard wall -- is
   itself scale-invariant and never blocks it). A soft penalty
   kappa_v*(V-V_target)^2 targets that direction specifically.
   Honest note on getting the test right: my first attempt tried to show
   the effect via full MCMC traces (mean action across a kappa sweep,
   500-6000 sweeps on the 8-vertex/6-tet test cube), comparing constrained
   vs. unconstrained. This was too noisy to be a reliable test -- on a
   lattice this small, a diffusive random walk with small step_size simply
   doesn't drift far enough in 500-6000 sweeps to show a clean runaway
   signature either way (the "runaway" is a genuine long-run/large-step-size
   asymptotic property, not something a short MCMC trace reliably exhibits).
   Replaced with a deterministic test of the actual claimed mechanism:
   confirmed analytically that the curvature term scales exactly linearly
   under a pure rescale, then directly computed the Metropolis d_s for (a)
   a coherent global rescale in the runaway direction and (b) an ordinary
   single-edge shape move, confirming the volume penalty makes (a)
   effectively unacceptable (d_s > 20, so exp(-d_s) ~ 2e-9) while barely
   touching (b) (penalty contribution < 1.0 vs. the same run's kappa*Δaction
   scale). This tests the mechanism directly rather than hoping an
   emergent MCMC trace reveals it. `McResult` also now always reports
   volume_trace/mean_edge_length_trace/conformal_drift() diagnostics
   (previously invisible in the returned statistics). 2 new tests.

   threshold, not an unexplained magic number. Added `connectivity_eps(n,
   target_fail_prob)`, a finite-N formula calibrated to a stated
   reliability target (via the isolated-vertex Poisson approximation)
   rather than a fixed multiplier -- its implied margin shrinks (slowly --
   only like 1/ln(N)) as N grows.
